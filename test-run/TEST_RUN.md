# Тестовый прогон `project_setup.sh` в QEMU

**Это не результаты сдачи.** Файлы получены при проверке скрипта `project_setup.sh` на тестовой виртуальной машине,
которую Claude (ИИ-ассистент) развернул в облачном контейнере. Скрипт запускался на ней без участия студента.

| Параметр | Тестовая ВМ |
|---|---|
| Образ | Fedora 43 Cloud Base, x86_64 |
| Виртуализация | QEMU, программная эмуляция (TCG) |
| SELinux | Enforcing |
| Сеть | user-mode QEMU: IP `10.0.2.15/24`, шлюз `10.0.2.2`, DNS `10.0.2.3` (вместо `192.168.1.100` из ТЗ) |
| Диск под данные | `/dev/vdb`, 2 ГБ |

Запуск:

```bash
echo YES | sudo DISK=/dev/vdb IP=10.0.2.15/24 GW=10.0.2.2 DNS=10.0.2.3 bash project_setup.sh > run.log 2>&1
```

Код выхода — 0. В `run.log` лежит полный вывод скрипта с трассировкой (`set -x`), в `project_history.txt` — история команд.
Скриншот снят браузером Chromium (Playwright) со страницы, которую отдаёт nginx тестовой ВМ.

Перед этим прогоном на той же ВМ проверялось следующее:
* повторный запуск, когда пользователь, группа, запись в fstab и правило SELinux уже существуют;
* перезагрузка: после неё сохраняются монтирование по метке, автозапуск nginx, контекст SELinux и capabilities;
* вход root по SSH отклоняется;
* `mephi-admin` захватывает трафик tcpdump без sudo.
